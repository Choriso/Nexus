# Nexus — ML и AI-переключатель

Этот документ описывает:

- как запускать обучение ML-модели;
- как переключать использование ИИ в коде.

## 1. Обучение модели

Все ML-скрипты находятся в директории `ml/` (см. также `ml/README.md`).

- `ml/train.py` — основной вход обучения;
- `ml/test_model.py` — быстрая проверка артефактов.

### Запуск обучения

```bash
python -m ml.train
```

После выполнения скрипта в `ml/artifacts/` появятся артефакты (в демонстрационной версии — `model_stub.json`).

### Проверка модели

```bash
python -m ml.test_model
```

Если всё в порядке, скрипт завершится без ошибок и выведет сообщение о прохождении проверки.

## 2. Переключение ИИ в приложении

Новый AI-сервис реализован в модуле `src/services/ai_service.py` и использует паттерн **Strategy** + фабрику.

### Переменные окружения

В `.env` добавлены переменные:

- `AI_ENABLED` — глобальный флаг включения ИИ:
  - `true` / `1` / `yes` / `on` — ИИ включён;
  - любое другое значение — ИИ выключен (используется мок-сервис).
- `AI_PROVIDER` — выбор стратегии:
  - `local` — локальная модель/прокси (`LocalAIService`);
  - `external` — внешний провайдер (`ExternalAIService`).

Пример блока в `.env`:

```dotenv
AI_ENABLED=true
AI_PROVIDER=local
```

### Использование в коде

```python
from src.services.ai_service import get_ai_service

ai = get_ai_service()
reply = ai.generate_reply("Привет! Расскажи о себе.")
```

- При `AI_ENABLED=false` вернётся предсказуемый мок-ответ.
- При `AI_ENABLED=true` и `AI_PROVIDER=local` будет использована локальная стратегия.
- При `AI_ENABLED=true` и `AI_PROVIDER=external` — стратегия внешнего провайдера.

Реальные вызовы к локальной/внешней модели можно инкапсулировать внутри `LocalAIService` и `ExternalAIService`, не трогая остальной код. Это позволяет расширять функциональность без переписывания базы и бизнес-логики.
